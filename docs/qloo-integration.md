# Qloo cultural intelligence

KREV's Culture Graph turns a company goal, audience, geography, and a handful of cultural references into taste-graph evidence that can ground audience analysis and campaign planning. The evidence is retrieved from Qloo's Insights and entity search APIs; it is not generated by the language model alone.

## Configure the key

Add these variables to the server environment (Render: Dashboard → service → Environment):

```env
QLOO_API_KEY=your_event_or_workspace_key
# Optional when Qloo gives you a non-default API host
QLOO_BASE_URL=https://api.qloo.com
```

Keep the key server-side. It is read only by `src/lib/qloo/client.ts`, sent in the `X-Api-Key` header, and never exposed to the browser. Do not commit it to `.env`, `.env.local`, logs, screenshots, or client bundles. Restart/redeploy the service after adding it.

## User flow

1. Open a company dashboard and choose **Culture Graph**.
2. Enter the campaign goal, audience, and optional geography.
3. Add one to five cultural seeds (a brand, artist, film, place, or similar reference).
4. Choose up to four cultural categories.
5. Select **Build cultural profile**.

The result contains resolved Qloo entities, affinity signals, tags, and explainability data. When the user has a verified KREV provider key, the same request also produces a concise campaign-direction draft grounded in those Qloo signals. A strategist can review the evidence and draft before using any recommendation in a public campaign.

## API surface

- `GET /api/qloo/search?q=...&type=brand` — authenticated entity search.
- `POST /api/qloo/insights` — authenticated, validated Insights request.
- `POST /api/cultural-intelligence/analyze` — authenticated, company-scoped workflow used by the Culture Graph page.

All request bodies are bounded with Zod, seed IDs and result counts are capped, and requests fail with a safe configuration message when `QLOO_API_KEY` is absent. The no-key state is intentional: KREV does not fabricate cultural evidence or silently fall back to generic LLM output.

## Production notes

Qloo quotas and event credentials vary by account. Use the smallest useful seed set, keep the category selection focused, and add a bounded retry strategy only after observing the provider's limits. The current workflow runs one category request at a time to keep quota use predictable. If the key is unavailable, the rest of KREV continues to work and the Culture Graph shows a recoverable error.
